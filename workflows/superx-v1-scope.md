# SuperX 截图范围复刻：第一版

状态：第一版交互骨架已实现，仍有下列验收差距。

## 目标

在现有 Signal Agent 项目中，复刻用户提供的 SuperX 截图所呈现的主要功能与连续操作路径。截图是验收依据；截图没有展示但完成操作所必需的页面、交互和状态由本项目设计补全，并在规格中标记为推断设计。

## 已确认模块

| 模块 | 截图可核对的能力 | 待补全的关键操作 |
| --- | --- | --- |
| Signals | 监测来源、匹配评分、线索列表与理由、运行进度 | 创建与编辑 Agent、审核与管理线索 |
| Workers | 声音与规则配置、按需或定时生成、人工审核原则 | 草稿结果、修改、批准进入草稿或队列 |
| Inspiration | 帖子与媒体搜索、时间和账号筛选、内容卡片 | 详情、收藏或用于创作的路径 |
| 内容发布与队列 | 发帖入口、按日期排列的发布时间槽 | 编辑、预览、草稿、上传媒体、排期、发布、改期 |
| Analytics | 粉丝增长、表现最佳帖子、时间范围、导出入口 | 各指标详情、筛选及导出内容 |
| Contacts | 线索进入联系人列表的路径与导航入口 | 联系人详情、分组、状态与跟进记录 |
| DMs | 收件人、消息变量、预览、发送队列和历史 | 收件人选择、失败处理、暂停与恢复 |
| Context | 关于你、受众、写作风格、兴趣、产品 | 保存与重新生成、规则优先级及产品编辑 |
| 账号设置 | General、Appearance、Billing、Team、Context、API/MCP/CLI | 各设置的保存、权限和错误状态 |

## 已有基础

现有 Signals 原型支持手动真实 X 数据读取、规则评分和本地线索保存。`workflows/acquisition.md` 描述了另一个已实现的每日获客简报工作流；它可作为 Signals 的基础，但不等同于完整的 SuperX 模块复刻。

## 当前实现与验收差距

| 模块 | 已实现 | 仍需实现 |
| --- | --- | --- |
| Signals | 原有监测和评分、线索加入 Contacts | 更完整的 Agent 运行状态 |
| Workers | 预设或自建配置、三种模板结构、暂停/启用、写作简报、逐篇修改及指定时间排期审核 | AI 写作、真实声音学习、定时运行和自动执行额外要求 |
| Inspiration | X 近期帖子和媒体搜索、本次结果筛选、收藏标记、从帖子创建灵感草稿 | 截图中的跨平台媒体源、服务端时间和账号搜索筛选、可跨搜索查看的收藏库 |
| 内容发布与队列 | 草稿、按账号时区排期和改期、人工确认后通过 X 发布 | 媒体上传、自动到点提醒或发布 |
| Analytics | 手动读取当前粉丝数与近期帖子表现、每日粉丝快照、7/30/90 天增长曲线与筛选、按筛选结果 JSON 导出 | 自动连续采集、完整指标和表格导出 |
| Contacts | Signals 线索加入、手动增删、状态和分组筛选、备注编辑、跟进记录、账号级服务端保存 | 更细的活动历史与冲突提示 |
| DMs | 收件人、变量预览、待发送列表、暂停和删除 | 获得明确同意后的真实发送、送达和失败状态 |
| Context | 关于你、受众、风格、兴趣、产品的编辑和账号级服务端保存 | 根据帖子重新生成、规则优先级 |
| 账号设置 | General、Appearance、Billing 演示流程、Team 导航、Context 导航 | API/MCP/CLI 密钥和连接、真实账单入口整合 |

Studio 数据按登录用户保存到数据库，当前浏览器的 localStorage 用于快速显示和云端故障时的本地备份。已有本地数据在首次访问时迁入账号；同时在两台设备上编辑同一份数据时采用版本检查和重试，极端冲突仍可能需要刷新后重试。X 读取可能受权限和付费额度限制。Billing 是明确标注的演示数据，不会收款或取消真实订阅。

## 视觉决定

用户要求继续；暂按前一轮推荐方案推进：页面布局、信息层级和交互尽量贴近截图，产品名称继续使用 Signal Agent。这个假设可在设计实现阶段调整。

## 计费决定

用户要求继续；暂按前一轮推荐方案推进：第一版完成截图中的试用额度、订阅、发票、取消流程的可操作界面，使用测试数据，不接真实支付。正式收费前需另行定义价格、支付服务、账单与数据保留规则。

详细设计将按模块分别写入 `workflows/*.md`，并记录触发方式、用户检查点、数据来源、完成条件和故障恢复。
