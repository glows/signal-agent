# 获客循环

状态：第一版已实现。生产部署尚未执行。

## 目标与操作

用户配置一个产品、理想客户画像和 1–3 个监测来源；每天收集与需求相关的 X 线索，在 App 的 `/brief` 页面审核，并记录值得跟进、不合适、已联系或待审核状态。

## 触发与日程

- 默认自动发现关闭，用户保存配置并勾选开启后每天北京时间 09:00 运行一次。
- 生产 Worker 每 5 分钟扫一次到期配置；本地 API 每分钟扫描，需保持服务进程在线。
- 错过的日程只补跑一次，不回放历史每一天。
- 保留手动发现。手动和自动任务共享同一天的预算，不会并行执行。

## 数据与预算

- 每个账号第一版支持一个获客配置，1–3 个关键词、账号或列表来源。
- 每日帖子读取预算默认 30，可选 60 或 100，在来源之间分配。
- 运行开始在数据库事务中预留预算。失败或中断不退回预算，当天不自动重试；预算按北京时间日期重置。
- 预算限制帖子数量，不是美元费用上限。账号资料查询可能额外计费。
- 402 或接口配置权限错误暂停自动发现，简报运行记录显示原因；修复后用户重新开启。
- OAuth 使用现有 Better Auth 的加密令牌存储与刷新。后台通过受信任的服务端调用按用户取令牌，不依赖浏览器会话。

## 匹配、去重和保留

- 当前评分仍使用规则算法与理想客户画像，不调用大模型。
- 收集分数至少 60 的线索，按 X 用户 ID 去重，保留已有审核反馈。
- 第一版最多保留最近 1000 条线索和 60 次运行。超出保留范围的历史用户可能再次出现。
- 跟进建议根据来源文本生成，提示先验证问题与现有方案，不自动发送任何消息。

## 简报与检查点

App 显示产品目标、定时状态、下次运行时间、待审核数量、匹配理由、来源帖子、建议和运行记录。用户能按审核状态筛选并更新反馈。

数据库按登录用户隔离配置、线索及运行记录，支持跨设备读取。现有演示工作台与手动 Agent 页面继续保留；每日简报通过侧栏入口进入，首次使用需单独配置获客目标。

## 故障与恢复

任务持有 10 分钟租约。并发触发会被拒绝；过期租约允许之后的任务恢复，旧运行显示中断或超时。网络或授权刷新失败会写入安全的失败信息，不保存令牌或原始服务端异常。

## 部署与验证

新增 `acquisition` 表的增量迁移已获用户明确授权并应用到配置的 Neon 数据库。Cloudflare Cron 配置已写入仓库，但需部署后才在生产执行。

测试使用 PGlite 实际迁移，覆盖用户隔离、未登录拒绝、北京时间日程、并发任务、每日预算和 402 后暂停。不以真实付费 X 调用作为自动测试。
